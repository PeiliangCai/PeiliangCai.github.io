# 一、简介
Agent Memory：让智能体在多轮交互、多任务、多环境中，**把有价值的信息保存下来**，并在未来合适的时候检索、更新、遗忘和利用。
# 二、记忆的类型

| 记忆类型                    | 作用                                     | 存储方式                            |
| ----------------------- | -------------------------------------- | ------------------------------- |
| 短期记忆 Short-term Memory  | 当前任务上下文（为了完成当前任务，Agent 临时需要保存和使用的全部信息） | Prompt / Context Window / Redis |
| 工作记忆 Working Memory     | 当前推理过程中的中间状态                           | JSON State / Scratchpad         |
| 长期语义记忆 Semantic Memory  | 稳定事实和知识                                | 向量库 + 结构化数据库                    |
| 情景记忆 Episodic Memory    | 过去发生过的事件                               | 事件日志 + 向量索引                     |
| 程序性记忆 Procedural Memory | 做事方法/技能                                | Rule / Skill / Workflow         |
一个完整的 agent memory 往往包含多种记忆类型。一个完整的 Agent 不是只做“向量检索历史对话”，而是要同时维护这些不同层级的记忆。
# 三、记忆系统的实现
## 3.1 记忆写入机制
并不是所有的内容都应该写入长期记忆，可以通过实现一个 Memory Writer 做筛选。可以写入的内容如下：
1. 长期稳定的用户偏好
2. 长期项目背景
3. 已完成任务的关键结论
4. 重复出现的问题和解决方案
5. 用户明确要求“记住”的信息
6. Agent 自己总结出的经验规则
---
记忆写入的格式尽量不要是纯文本，而是结构化对象，方便后期==**排序、遗忘、更新、冲突检测**==。
## 3.2 记忆检索机制
简介：比较简单的就是通过向量相似度进行检索，但 Agent 记忆检索一般不应该只靠相似度。
Agent 中常比较复杂，需要根据相关性、重要性、近因性等因素来综合决定哪些记忆进入上下文。
## 3.3 记忆管理机制：更新、合并、遗忘
### 3.3.1 更新机制
当新记忆与旧记忆相关时，不一定新增，而是更新。避免新旧记忆发生冲突。
### 3.3.2 冲突检测
例子：
旧记忆：用户使用 Windows + WSL
新记忆：用户现在在 AutoDL Linux 容器中调试 Codex CLI
这种就不是冲突，而是不同的环境；应该加上作用域。
### 3.3.3 遗忘机制
可以设置：
1. 时间衰减：长期未访问的低重要性记忆逐渐降权。
2. 用户删除：用户要求忘记时必须删除。
3. 过期删除：如临时任务、验证码、一次性链接。
4. 摘要替代：把多个细节压缩成一个高层摘要。
# 四、记忆系统的架构范式
## 4.1 Buffer / Context-based Memory
**上下文缓冲型记忆**（最基础、短期记忆形式）
核心思想：把**最近的对话历史、工具调用结果、当前任务状态**直接放进上下文窗口。

优点：适合短任务、多轮聊天、简单 Agent loop。
缺点：上下文窗口有限，随着任务变长，早期信息会被截断或者被 compact 后丢失细节。
## 4.2 Vector-store Long-term Memory
**向量数据库长期记忆架构**（最常见的工程实现方式）
核心思想：把历史对话、事件、用户偏好、任务结果切成 memory chunks，生成 embedding，存入向量数据库；之后根据当前问题做相似度检索，再注入上下文。

优点：简单、通用、容易接入 RAG。很多 Agent 系统的长期记忆实际上就是一个面向历史交互的 RAG。
缺点：它通常只解决“相似记忆检索”，不天然解决记忆更新、冲突消解、遗忘、抽象总结等问题。
## 4.3 Hierarchical Memory
**分层记忆架构**
该类架构常把记忆分成多层，常见是：
1. 短期记忆
2. 长期记忆
3. 工作记忆
特点：agent 主动**管理**记忆
## 4.4 Reflection-based Memory
**反思摘要型记忆架构**
这类架构不是简单保存原始事件，而是让 Agent 对历史进行总结、抽象和归纳。
特点：不是只记住发生过什么，而是归纳出“这说明了什么”。

优点：
1. 降低记忆噪声
2. 形成高层用户画像或任务画像
3. 更适合长期任务
4. 能支持计划生成

缺点：
1. 反思摘要可能丢失细节
2. 可能产生错误抽象（与 agent 的能力有关）
3. 需要保留原始记忆以便**回溯**
## 4.5 Structured / Symbolic Memory
**结构化符号记忆架构**
特点：这类架构不只是把记忆当文本块，而是存成==结构化数据==。

优点：可靠、可控、容易更新
缺点：schema 设计成本较高，面对开放域信息时不如向量记忆灵活。

在真实产品中，结构化记忆通常会和向量记忆混合使用。
## 4.6 Graph-based Memory
**图结构记忆架构**
特点：这类架构把记忆组织成图，而不是孤立文本块。

优点：
1. 适合复杂长期项目
2. 支持多跳记忆检索
3. 能表达记忆之间的关系
4. 比纯向量检索更可解释

缺点：
1. 构图成本高
2. 关系抽取可能出错
3. 图更新和冲突处理复杂
## 4.7 Agentic / Self-organizing Memory
**自组织智能体记忆架构**
核心思想：记忆系统本身也由 Agent 管理，而不是固定规则管理。也就是说 Agent 能**自主决定**：
1. 这条信息要不要记
2. 应该记成什么形式
3. 应该和哪些旧记忆建立连接
4. 哪些旧记忆需要更新
5. 哪些记忆应该合并、遗忘或降权

优点：
1. 适合长期复杂任务
2. 能动态适应不同任务
3. 比固定 schema 更灵活
4. 更接近“经验积累”而不是简单数据库

缺点：
1. 成本高
2. 可控性弱
3. 评估困难
4. 容易出现错误记忆强化
## 4.8 Experience / Skill Memory
**经验库 / 技能库型记忆架构**
特点：这类架构关注的不是“用户说过什么”，而是“Agent 做过什么、学会了什么“。
典型记忆内容包括：
1. 任务成功经验
2. 错误修复步骤
3. 工具调用模式
4. 可复用代码片段
5. 子任务规划模板
6. 失败案例和规避规则
这种记忆适合工具型 Agent、代码 Agent、科研实验 Agent。它和普通用户记忆不同，更像是 Agent 的”程序性记忆“。

==感觉这个比较契合 Agentic RAG==
