## 2. Why We Learn Static Analysis?
Static Analysis 重要性：
1. Program Reliability
	1. Null pointer dereference, memory leak, etc.
2. Program Security
	1. Private information leak, injection attack, etc.
3. Compiler Optimization
	1. Dead code elimination, code motion, etc.
4. Program Understanding
	1. IDE call hierarchy, type indication, etc.
## 3.  What is Static Analysis?
Static analysis analyzes a program P to reason about its behaviors and determines whether it satisfies some properties before running P.
静态分析可以做的事情：
	- P 是否包含任何隐私信息泄露
	- P 是否解引用任何空指针
	- P 中的 cast 操作是否安全
	- 是否存在死代码等等
	- ...
上述定义是理想状态下的静态分析，由 Rice‘s Theorem 可知，并不存在一个方法能够准确的判断出一个程序是否存在上述各个问题。

补充：静态分析是在不运行程序的情况下分析程序性质的方法。词法、语法、基础语义检查也属于静态处理，但在软件分析课程中，“静态分析”通常特指更高级的程序行为分析，比如数据流分析、指针分析、可达性分析、污点分析、死代码检测等。

### 3.1 静态分析中的两个重要性质
Perfect static analysis：**Sound** AND **Complete**
1. Sound
2. Complete
![[Pasted image 20260603212544.png|697]]
Truth 表示真实程序中存在的问题，
而 Sound 属性的静态分析能够把所有 Truth 中的问题全部指出但可能会误报；
而 Complete 属性的静态分析分析出的问题均包含在 Truth 中，但存在遗漏。

### 3.2 既然完美的静态分析不存在，那该如何设计静态分析呢？
![[Pasted image 20260603213016.png]]
1. false negatives（漏报）：妥协 soundness，表示忽视某些报错，最终报错的内容为 Truth 的子集。
2. false positives（误报）：妥协 complete，表示更严格的报错，导致有些报错并不存在于 Truth 的集合中。

结论：大部分情况会选择 **Compromise completeness**（即 Sound）。
原因：Sound 的分析更不容易漏掉潜在错误

## 2. AST vs. IR
AST：
- high-level and closed to grammar structure
- usually language dependent
- suitable for fast type checking
- lack of control flow information

IR：
- low-level and closed to machine code
- usually language independent
- compact and uniform
- contains control flow information
- usually considered as the basis for static analysis

## 2. Preliminaries of Data Flow Analysis
### Input and Output States
- Each execution of an IR statement transforms an input state to a new output state
- The input(output) state is associated with the program point before(after) the statement
![[Pasted image 20260607152448.png]]

Data-flow analysis is to find a solution to a set of safe-approximation-directed constraints on the IN[s]'s and OUT[s]'s, for all statements s.
- constraints based on semantics of statement(transfer functions)
- constraints based on the flows of control

### 数据流事实（IN and OUT）
定义：数据流事实就是我们希望分析的信息。

不同分析关心的信息不同。

|分析|数据流事实|
|---|---|
|Reaching Definitions|可能到达当前位置的变量定义|
|Live Variables|当前位置之后可能被使用的变量|
|Available Expressions|已经计算且仍然有效的表达式|
|Constant Propagation|变量可能对应的常量值|
|Pointer Analysis|变量可能指向的对象|

因此，`IN` 和 `OUT` 的具体含义并不固定。

## 3. Reaching Definitions Analysis（I）
### Reaching Definitions
A definition d at program point p reaches a point q if there is a path from p to q such that d is not "killed" along that path
- A definition of a variable v is a statement that assigns a value to v
- 上述内容可以简述为从 p 到 q 之间，变量 v 没有新的赋值
- Reaching definitions can be used to detect possible undefined variables. e.g., introduce a dummy definition(可以理解为在程序执行之前，定义所有变量为 undefined) for each variable v at the entry of CFG, and if the dummy definition of v reaches a point p where v is used, then v may be used before definition (as undefined reaches v)

## 1. Iterative Algorithm, Another View
### Q：新在哪？
A：
	原本的视角是**局部视角**，是逐个节点计算 IN 和 OUT，并且由 transfer function 可知当 IN/OUT 相同时，下一个节点的 OUT/IN 均相同，则算法终止。

		假定有 k 个节点，则所有节点的输出为：
			（OUT[n_1], OUT[n_2], ..., OUT[n_k]）
		将其视为 (V_1 × V_2 × ... × V_k)，并用V-k（k 是上标）
	那么转移函数为 F: V-k -> V-k，当输入输出相同时则算法终止。

## 4. Lattice, Semi-lattice, Complete and Product Lattice
### Lattice
一个偏序集：
如果任意两个元素 a, b ∈ P，都存在：
1. 最小上界
2. 最大下界
那么这个偏序集就是一个 **Lattice**。

简单说：
> Lattice = 任意两个元素都有 Join 和 Meet 的 Poset。

### Semi-lattice
如果一个偏序集只保证任意两个元素都有 Join 或者都有 Meet，那么它就是 **Semilattice**。  
  
Semilattice 分为两种：  
1. **Join Semilattice**  
2. **Meet Semilattice**  
  
#### Join Semilattice  
如果任意两个元素 \(a,b\) 都存在 Join：  
那么它是一个 **Join Semilattice**。  
  
也就是说：  
> 任意两个元素都有最小上界。

#### Meet Semilattice  
如果任意两个元素 \(a,b\) 都存在 Meet：  
那么它是一个 **Meet Semilattice**。  
  
也就是说：  
> 任意两个元素都有最大下界。


#### Lattice 和 Semilattice 的区别

| 概念 | 要求 |
|---|---|
| Join Semilattice | 任意两个元素都有 Join |
| Meet Semilattice | 任意两个元素都有 Meet |
| Lattice | 任意两个元素既有 Join，又有 Meet |

所以：
Lattice = Join Lattice + Meet Lattice

简单理解：
> Semilattice 只要求一边存在；Lattice 要求两边都存在。

### Complete Lattice：完全格
一个偏序集：
如果它的任意子集 S 都存在：
1. 最小上界
2. 最大下界
那么它就是一个 **Complete Lattice**。

注意：
> Lattice 只要求**任意两个元素**有 Join 和 Meet；  
> Complete Lattice 要求**任意子集**都有 Join 和 Meet。

这里的任意子集可以包含：
- 0 个元素
- 1 个元素
- 2 个元素
- 有限多个元素
- 无限多个元素

注意：
1. every finite lattice (P is finite) is a complete lattice.
2. 最小上界 = ∪
3. 最大下界 = ∩

### Product Lattice：积格
假设有两个 Lattice （多个 Lattice 类似）：
L_1 = (P_1, **⪯**)
L_2 = (P_2, **⪯**)

那么它们的笛卡尔积：
P_1 × P_2
也可以构成一个 Lattice，称为 **Product Lattice**。

其中元素是二元组：
(x_1, x_2)

偏序关系按分量比较：
(x_1,x_2) **⪯** (y_1,y_2)

当且仅当：
x_1 **⪯** y_1  并且  x_2 **⪯** y_2

简单说：
> Product Lattice 中，两个元素比较大小时，每个分量都要分别比较。

性质：
1. A product lattice is a lattice
2. If a product lattice L is a product of complete lattices, then L is also complete

### Dispatch 和 Resolution
在 Call Graph Construction 里，**dispatch** 和 **resolution** 都是用来确定“一个调用点可能调用到哪些方法”的，但它们的层次不同。

可以先记一句话：
> **dispatch 解决：给定一个具体运行时类型，应该调用哪个方法。**  
> **resolution 解决：给定一个调用语句，可能有哪些目标方法。**

#### Dispatch
`Dispatch(c, m)` 的作用是：
> 已知接收者对象的运行时类型是类 `c`，并且要调用方法签名 `m`，找到真正会执行的那个方法实现。

形式上可以理解为：
```
Dispatch(class, method signature) -> concrete method
```

![[Pasted image 20260622113653.png]]
补充：
- 如果该类中没有对应方法，则去父类中寻找（子类可以继承父类的方法）

---
#### Resolution
`Resolution` 的作用是：
> 对一个具体的调用语句，找出它可能调用到的所有目标方法。

形式上可以理解为：
```
Resolve(call site) -> set of target methods
```

![[Pasted image 20260622113741.png]]
	注意：第三个 if 中所提的 c 的子类包括所有的直接和非直接的子类。

---
#### 两者的区别

| 对比项        | Dispatch            | Resolution    |
| ---------- | ------------------- | ------------- |
| 输入         | 一个具体类 + 方法签名        | 一个调用点         |
| 输出         | 一个具体目标方法            | 一组可能目标方法      |
| 解决的问题      | 如果对象运行时类型确定，该调用哪个方法 | 这个调用点可能调用哪些方法 |
| 层次         | 类级别                 | 调用点级别         |
| 是否考虑多个可能类型 | 不考虑，只处理一个类型         | 会考虑多个可能类型     |

- Disadvantage: imprecise

## 3. Interprocedural Control-Flow Graph
ICFG 表示整个程序的结构。
一个程序的 ICFG 由该程序中的方法的 CFGs 组成，并且包含两种额外的边：
1. Call edges: from call sites to the entry nodes of their callees
2. Return edges: from return statements of the callees to the statements following their call sites (i.e., return sites)
3. 解释：
	1. call site 是指调用函数的语句
	2. return site 是指紧跟着 call site 的语句
4. ICFG = CFGs + call & return edges
5. call graph 就是用于获取这两种边的信息

- For object-oriented programs (focus on java)

- Regarded as a may-analysis
	- Computes an over-approximation of the set of objects that a pointer can point to, i.e., we ask "a pointer may point to which objects?"
### Application of Pointer Analysis
- Fundamental information
	- Call graph, aliases, ...
- Compiler optimization
	- Virtual call inlining, ...

# 九、Static Analysis for Security
## 1、Information Flow Security
### Access Control vs. Information Flow Security
- Access control (a standard way to protect sensitive data)
	- Checks if the program has the rights/permissions to access certain information
	- Concerns how information is accessed
- Information flow security (end-to-end)
	- Tracks how information flows through the program to make sure that the program handles the information security
	- Concerns how information is propagated
- 总结：权限控制相当于点，而信息流安全则是线。（一个相当于门卫，另一个则是从门卫到端之间如何保证安全）两者之间是互补的。
### Information Flow Definition
Information flow: if the information in variable x is transferred to variable y, then there is information flow x -> y
![[Pasted image 20260626183827.png]]

---
### Information Flow Security
Connects information flow to security
- Classifies program variables into different security levels
- Specifies permissible flows between these levels, i.e., information flow policy

### Security Levels (Classes)
The most basic model is two-level policy, i.e., a variable is classified into one of two security levels:
1. H, meaning high security, secret information
2. L, meaning low security, public observable information
Security levels can be modeled as *lattice*
- L <= H
### Information Flow Policy
- 限制信息在不同安全层级之间的流动
- Noninterference policy（一种策略）
	- 要求高层级变量的信息不会影响底层级变量的信息
	- 直观上，不应该通过观察底层级变量来推断出关于高层级变量的任何信息

# 十一、简答题（自己总结的）
## 1. Introduction
1. 静态分析定义：静态分析在运行一个程序之前分析它。
2. 静态分析有什么应用：静态分析可用于程序可靠性、安全性、编译优化和程序理解，例如检测空指针、隐私泄露、死代码以及构建调用关系等。
3. Static Analysis = Abstraction + Over-approximation
4. Sound：不漏报，可能误报
5. Complete：不误报，可能漏报
6. 大多数静态分析更偏向 soundness：因为安全性和可靠性分析中，漏报潜在错误通常更危险。
7. False Positive：报了但实际没有
8. False Negative：实际有但没报
9. 误报的来源：误报不一定都来自不可执行控制流路径；它们本质上来自静态分析的 **abstraction** 和 **over-approximation**。不可行路径只是 control-flow over-approximation 的一种典型表现。
10. 为什么静态分析通常要做 over-approximation：静态分析通常做 over-approximation，是为了保证 soundness，尽量不漏掉潜在错误（因为有些潜在的错误会带来更严重的后果）；代价是可能考虑到动态运行时不会发生的情况，因此产生 false positives。
11. Rice 定理：对于递归可枚举语言中的程序，任何关于程序行为的非平凡性质都是不可判定的。
	1. non-trivial property（非平凡性质）：不是对所有程序都成立，也不是对所有程序都不成立的性质。
	2. 意义：Perfect static analysis 不存在（不存在一个通用的、对所有程序都能给出完全精确 Yes/No 答案的静态分析器）
12. abstraction 和 over-approximation 的意义：
	1. abstraction：用抽象表示无限复杂的程序运行状态
	2. over-approximation：用近似保证分析在有限时间内完成
## 2. Intermediate Representation
1. 为什么静态分析通常基于 IR：IR 是源代码和静态分析之间的中间层，目的是把复杂、多样的源程序转换成统一、简单、适合分析的形式。
2. AST vs. IR：AST 适合**表达语法结构**，IR 适合做**静态分析**。
	1. AST：高层、接近语法、语言相关、缺少控制流信息
	2. IR：低层、接近机器码、较语言无关、紧凑统一、包含控制流信息
3. 3AC：等号右侧最多一个操作符
4. Jimple：Soot 的 typed 3-address code
5. Basic Block：只能从第一条语句进入，只能从最后一条语句退出
6. CFG：节点是基本块、边表示可能的控制流

# 4. Data Flow Analysis -- Foundations
1. 数据流分析可以看成在有限格上反复应用单调函数，最终达到不动点。
2. Partial order：partial order 是满足自反性、反对称性和传递性的二元关系。
3. Lattice = 偏序集 + 任意两个元素都有 LUB 和 GLB
4. Semilattice = 偏序集 + 任意两个元素都有 LUB 或 GLB
5. Complete Lattice = 偏序集 + 任意子集都有 LUB 和 GLB
6. 给定 complete lattice，如果 `f: L → L` 是 monotonic，并且 L 是 finite，那么从 bottom 不断迭代可以找到 least fixed point；从 top 不断迭代可以找到 greatest fixed point。
7. 数据流分析的迭代过程可以看作在有限积格上反复应用一个单调函数，因此根据不动点定理，迭代会在有限步内达到不动点。
8. MOP = **Meet Over all Paths**。
	1. MOP[p] = result(path1) meet result(path2) meet result(path3)
9. Constant propagation 是 monotonic but not distributive，因为其 transfer function 不一定满足 f(x meet y)=f(x) meet f(y)。
```
Partial order：自反性、反对称性、传递性
Lattice：任意两个元素都有 LUB 和 GLB
Complete lattice：任意子集都有 LUB 和 GLB
Product lattice：多个格的笛卡尔积，仍可构成格
Monotonicity：x ⊑ y => f(x) ⊑ f(y)
Fixed point：f(x) = x
Fixed-point theorem：finite lattice + monotonic function => 迭代可达不动点
May analysis：通常 meet = ∪
Must analysis：通常 meet = ∩
MOP：Meet Over all Paths
Distributive：迭代解可等于 MOP
Constant Propagation：monotonic but not distributive
```
