# Day 1：课程框架与复杂度分析
## 1.1 数据结构
数据结构：数据元素之间的关系，以及这些数据在计算机中的存储方式和操作方法。

数据结构 = 数据之间的关系 + 数据如何存储 + 数据如何操作

常见的数据结构包括：
- 线性表
- 栈
- 队列
- 树
- 图
- 哈希表
- 堆
## 1.2 数据结构的三要素
1. 逻辑结构：数据元素之间的逻辑关系
2. 存储结构：数据元素在计算机中的存储方式
3. 数据运算：对数据进行的基本操作，例如插入、删除、查找、遍历等。
## 1.3 逻辑结构
逻辑结构指的是数据元素之间的关系，与具体的存储方式无关

常见的逻辑结构：

| 逻辑结构 | 特点         | 例子       |
| ---- | ---------- | -------- |
| 集合结构 | 元素之间没有明显关系 | 一个班级的学生  |
| 线性结构 | 一对一关系      | 线性表、栈、队列 |
| 树形结构 | 一对多关系      | 二叉树、文件目录 |
| 图结构  | 多对多关系      | 社交网络、地图  |
## 1.4 存储结构
存储结构指数据在计算机内存中的实际存放方式。

常见存储结构：

| 存储结构 | 特点       | 例子        |
| ---- | -------- | --------- |
| 顺序存储 | 内存连续     | 数组、vector |
| 链式存储 | 用指针链接    | 链表        |
| 索引存储 | 额外建立索引表  | 数据库索引     |
| 散列存储 | 通过哈希函数定位 | 哈希表       |
注意：同一种逻辑结构可以有多种存储方式。
## 1.5 数据的运算

数据运算是指对数据结构进行的基本操作。

常见操作：
- 创建
- 插入
- 删除
- 查找
- 修改
- 排序
- 遍历
- 销毁

不同数据结构的操作效率不同。
例如数组查找位置快，但中间插入删除慢；链表插入删除方便，但随机访问慢。
## 1.6 抽象数据类型 ADT

ADT，即 Abstract Data Type，抽象数据类型。

它描述一种数据类型支持哪些操作，而不关心具体如何实现。

例如栈 ADT：
- push(x)：入栈
- pop()：出栈
- top()：获取栈顶元素
- empty()：判断栈是否为空

ADT 强调逻辑功能，具体实现可以不同。
例如栈可以用数组实现，也可以用链表实现。
## 1.7 算法是什么？

算法是为解决某个问题而设计的一组有限操作步骤。

算法通常作用在某种数据结构上。
例如：
- 在数组中查找元素
- 对链表进行反转
- 在图中寻找最短路径

算法的五个特性：
1. 有穷性：算法必须在有限步内结束
2. 确定性：每一步操作都有明确含义
3. 可行性：每一步都可以被执行
4. 输入：可以有 0 个或多个输入
5. 输出：必须有一个或多个输出

好算法的评价标准：
1. 正确性：算法能否正确解决问题。  
2. 可读性：代码是否容易理解和维护。  
3. 健壮性：对非法输入或特殊情况是否能正确处理。  
4. 时间效率：运行时间是否较短。  
5. 空间效率：占用内存是否较少。
## 1.8 复杂度分析
时间复杂度：随着输入规模 n 增大，算法运行时间**增长的趋势**。

它不关心具体运行了多少秒，而关心随着 n 变大，操作次数如何增长。  
  
例子：  
  
```cpp  
for (int i = 0; i < n; i++) {  
cout << i << endl;  
}
```

大 O 表示法用于表示算法复杂度的上界，通常表示最坏情况下的增长趋势。  
  
化简规则：  
  
1. 忽略常数项。  
2. 忽略低阶项。  
3. 忽略最高阶项的常数系数。  
  
例如：  
  
| 原始操作次数        | 时间复杂度      |
| ------------- | ---------- |
| 100           | O(1)       |
| 3n + 5        | O(n)       |
| 2n² + 10n + 7 | O(n²)      |
| n log n + n   | O(n log n) |

常见时间复杂度排序：
```
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
```
## 1.9 最好、最坏、平均时间复杂度

对于同一个算法，不同输入情况下运行时间可能不同。

以顺序查找为例：

```cpp
for (int i = 0; i < n; i++) {
    if (a[i] == target) return i;
}
return -1;
```
- 最好情况：目标元素在第一个位置，复杂度 O(1)。
- 最坏情况：目标元素在最后一个位置或不存在，复杂度 O(n)。
- 平均情况：目标元素可能出现在任意位置，复杂度 O(n)
## 1.10 空间复杂度

空间复杂度用于描述算法额外占用的存储空间随输入规模 n 增长的趋势。

通常只分析额外空间，不包括输入本身。

例 1：

```cpp
int sum = 0;
for (int i = 0; i < n; i++) {
    sum += a[i];
}
```
只使用常数个变量，因此空间复杂度为 O(1)。
## 1.11 C++ 代码复杂度分析方法

判断时间复杂度的方法：

1. 顺序执行的代码：复杂度相加，最后取最高阶。
2. 单层循环：通常是 O(n)。
3. 双重循环：通常是 O(n²)。
4. 每次规模减半：通常是 O(log n)。
5. 外层 n 次，内层 log n 次：通常是 O(n log n)。
6. 递归算法需要写递推式分析。
7. 最终结果忽略常数项和低阶项。

常见代码模式：

| 代码模式 | 时间复杂度 |
|---|---|
| 普通语句 | O(1) |
| 单层循环 | O(n) |
| 双重循环 | O(n²) |
| 三重循环 | O(n³) |
| 每次除以 2 | O(log n) |
| 排序中的分治 | O(n log n) |
# Day 2：顺序表、数组与 vector

## 2.1 线性表的定义
线性表是由 n 个数据元素组成的有限序列。

记作：
L = (a1, a2, a3, ..., an)

其中：
- a1 是第一个元素，没有直接前驱。
- an 是最后一个元素，没有直接后继。
- 中间每个元素都有唯一的直接前驱和唯一的直接后继。

线性表体现的是一种一对一的逻辑关系。
## 2.2 顺序表的定义

顺序表是线性表的顺序**存储结构**。

它用一组地址连续的存储单元，依次存放线性表中的数据元素。

顺序表中的元素在逻辑上相邻，在物理存储上也相邻。

举例：
```
逻辑结构：
[10, 20, 30, 40, 50]

物理存储：
地址 1000 -> 10
地址 1004 -> 20
地址 1008 -> 30
地址 1012 -> 40
地址 1016 -> 50
```
## 2.3 顺序存储结构的特点

顺序存储结构的特点：
1. 元素在内存中连续存放。
2. 支持随机访问。
3. 可以通过下标快速访问任意位置的元素。
4. 插入和删除时通常需要移动大量元素。
5. 存储空间通常需要提前分配，可能造成空间浪费或扩容开销。

核心特点：
随机访问快，插入删除慢。
## ## 2.4 数组与顺序表的关系
数组是一种连续存储结构，可以用来实现顺序表。

顺序表通常需要两个部分：
1. 存储空间：用于保存数据元素。
2. 当前长度：用于记录表中已有元素个数。

例如：
```cpp
int data[100];
int length;
```
其中：
- data 表示存储元素的数组。
- length 表示当前顺序表的长度。

## 2.5 C++ 数组的基本用法
C++ 数组是一段连续的存储空间。
定义数组：
```cpp
int a[5] = {1, 2, 3, 4, 5};
```
访问元素：
```
a[i]
```
数组下标从 0 开始。

数组的优点：
- 访问速度快。
- 内存连续。
- 实现简单。

数组的缺点：
- 长度固定。
- 插入删除不方便。
- 容易越界。
## 2.6 C++ vector 的基本用法
vector 是 C++ STL 提供的动态数组。

常见操作：
```cpp
vector<int> a;

a.push_back(10);      // 尾部插入
a.pop_back();         // 删除尾部元素
a.insert(a.begin(), 5); // 在指定位置插入
a.erase(a.begin());     // 删除指定位置元素
a.size();             // 当前元素个数
a.empty();            // 判断是否为空
a.clear();            // 清空 vector
```
vector 的特点：
- 底层是连续存储。
- 支持随机访问。
- 可以动态扩容。
- 中间插入和删除效率较低。
## 2.7 vector 的 size 与 capacity
vector 中有两个重要概念：
1. size：当前**实际存储**的元素个数。
2. capacity：当前已经**分配**的存储容量。
size <= capacity

当 push_back 导致 size 超过 capacity 时，vector 会自动扩容。

扩容通常会：
1. 申请一块更大的连续空间。
2. 将原来的元素复制或移动到新空间。
3. 释放旧空间。

因此，vector 尾插的平均复杂度是 O(1)，但某次扩容可能达到 O(n)。
## ## 2.8 顺序表的查找操作
顺序表的查找分为两类：
### 按位置查找
通过下标直接访问：
```cpp
data[i]
```
时间复杂度：O(1)
原因：顺序表内存连续，可以通过首地址和下标直接计算元素地址。

### 按值查找
从头到尾依次比较： 
```cpp
for (int i = 0; i < length; i++) {
    if (data[i] == x) return i;
}
return -1;
```
时间复杂度：O(n)
## 2.9 顺序表的插入操作
顺序表插入元素时，需要将插入位置及其后面的元素整体向后移动一位。

插入步骤：
1. 判断插入位置是否合法。
2. 判断顺序表是否已满。
3. 从最后一个元素开始向后移动。
4. 将新元素放入指定位置。
5. 表长 length 加 1。

示例：
```
原表：
[10, 20, 30, 40, 50]

在下标 2 插入 99：
[10, 20, 99, 30, 40, 50]

```
时间复杂度：
- 最好情况：在表尾插入，O(1)。
- 最坏情况：在表头插入，O(n)。
- 平均情况：O(n)。

C++代码：
```c++
bool insert(int pos, int x) {
    if (pos < 0 || pos > length) return false;
    if (length >= capacity) return false;

    for (int i = length; i > pos; i--) {
        data[i] = data[i - 1];
    }

    data[pos] = x;
    length++;
    return true;
}
```
注意：插入时移动方向是从后往前， 否则会覆盖原来的元素。
## 2.10 顺序表的删除操作
顺序表删除元素时，需要将被删除元素后面的元素整体向前移动一位。

删除步骤：
1. 判断删除位置是否合法。
2. 从删除位置的后一个元素开始向前移动。
3. 表长 length 减 1。

示例：
```
原表：
[10, 20, 30, 40, 50]

删除下标 2 的元素：
[10, 20, 40, 50]
```
时间复杂度：
- 最好情况：删除表尾元素，O(1)。
- 最坏情况：删除表头元素，O(n)。
- 平均情况：O(n)。
C++代码：
```c++
bool erase(int pos) {
    if (pos < 0 || pos >= length) return false;

    for (int i = pos; i < length - 1; i++) {
        data[i] = data[i + 1];
    }

    length--;
    return true;
}
```
注意：删除时移动方向是从前往后的。
## 2.11 顺序表操作复杂度分析

| 操作 | 时间复杂度 | 原因 |
|---|---:|---|
| 按下标访问 | O(1) | 可以通过下标直接计算地址 |
| 按值查找 | O(n) | 需要从头到尾扫描 |
| 表尾插入 | O(1) | 不需要移动元素 |
| 表头插入 | O(n) | 所有元素都要后移 |
| 中间插入 | O(n) | 平均需要移动一半元素 |
| 表尾删除 | O(1) | 不需要移动元素 |
| 表头删除 | O(n) | 所有后续元素都要前移 |
| 中间删除 | O(n) | 平均需要移动一半元素 |
| 遍历 | O(n) | 每个元素访问一次 |

## 2.12 顺序表的优缺点
顺序表的优点：  
1. 支持随机访问，可以通过下标 O(1) 访问元素。  
2. 存储密度高，不需要额外指针空间。（与链表进行对比的，链表还需要额外存储指针）
3. 内存连续，缓存友好，遍历效率高。  
4. 实现简单，适合元素数量相对固定的场景。

顺序表的缺点：  
1. 插入和删除需要移动元素，效率较低。  
2. 静态数组长度固定，空间不够灵活。  
3. 动态数组扩容时需要重新申请空间并移动元素。  
4. 需要一段连续的内存空间。  
5. 如果预分配空间过大，可能造成空间浪费。
## 2.13 顺序表与链表的初步对比

| 对比项 | 顺序表 | 链表 |
|---|---|---|
| 存储方式 | 连续存储 | 链式存储 |
| 随机访问 | 支持，O(1) | 不支持，O(n) |
| 插入删除 | 通常 O(n) | 已知位置时 O(1) |
| 空间利用 | 可能预分配浪费空间 | 每个结点需要额外指针 |
| 内存要求 | 需要连续空间 | 不需要连续空间 |
| 适合场景 | 经常访问、较少插入删除 | 经常插入删除 |

# Day 3：单链表基础
## 3.1 为什么需要链表
顺序表虽然支持 O(1) 随机访问，但插入和删除时需要移动元素，并且要求内存连续。

链表使用指针将结点连接起来，不要求物理存储连续。

链表适合插入、删除操作较多的场景。
## 3.2 单链表的定义
单链表是一种链式存储结构。

它由若干个结点组成，每个结点包含数据域和指针域。

数据域存放元素值，指针域存放下一个结点的地址。

最后一个结点的指针域为空，表示链表结束。
## 3.3 单链表结点结构

C++ 中单链表结点一般由数据域和指针域组成。

```cpp
struct ListNode {
    int val;
    ListNode* next;

    ListNode(int x) : val(x), next(nullptr) {}
};
```
其中：
- val 表示结点中的数据。
- next 表示指向下一个结点的指针。
- nullptr 表示当前结点后面没有其他结点。
## 3.4 头指针与头结点
头指针是指向链表第一个结点的指针。

头结点是在第一个有效数据结点之前额外设置的结点，通常不存储有效数据。

头结点的作用：
1. 统一链表插入和删除操作。
2. 避免对第一个结点进行特殊判断。
3. 方便处理空链表。

注意：
头指针一定存在，但头结点不一定存在。
## 3.5 空链表
不带头结点的空链表：
```cpp
head == nullptr
```

带头结点的空链表：
```c++
dummy->next == nullptr
```
链表题中要特别注意空链表情况，否则容易出现空指针访问错误。
## 3.6 单链表的遍历
单链表不能通过下标直接访问，只能从头指针开始，沿着 next 指针依次访问。

```cpp
void printList(ListNode* head) {
    ListNode* cur = head;

    while (cur != nullptr) {
        cout << cur->val << " ";
        cur = cur->next;
    }

    cout << endl;
}
```
时间复杂度：O(n)  
空间复杂度：O(1)
## 3.7 单链表的查找

单链表查找元素时，需要从头结点开始依次比较。

```cpp
ListNode* findValue(ListNode* head, int x) {
    ListNode* cur = head;

    while (cur != nullptr) {
        if (cur->val == x) {
            return cur;
        }
        cur = cur->next;
    }

    return nullptr;
}
```
时间复杂度：O(n)  
空间复杂度：O(1)
## 3.8 头插法建立链表
头插法是每次将新结点插入到**当前链表的头部**。

```cpp
ListNode* createByHeadInsert(vector<int>& nums) {
    ListNode* head = nullptr;

    for (int x : nums) {
        ListNode* node = new ListNode(x);
        node->next = head;
        head = node;
    }

    return head;
}
```
头插法特点：
- 插入方便。
- 每次插入位置都是表头。
- 最终链表顺序与输入顺序相反。
## 3.9 尾插法建立链表
尾插法是每次将新结点插入到当前链表的尾部。

```cpp
ListNode* createByTailInsert(vector<int>& nums) {
    ListNode* dummy = new ListNode(0);
    ListNode* tail = dummy;

    for (int x : nums) {
        tail->next = new ListNode(x);
        tail = tail->next;
    }

    ListNode* head = dummy->next;
    delete dummy;
    return head;
}
```
尾插法特点：
- 最终链表顺序与输入顺序一致。
- 需要维护尾指针 tail。
- 使用虚拟头结点可以简化代码。
## 3.10 单链表的插入操作
在结点 p 后插入新结点 node。

原关系：
```cpp
p -> p->next
```

插入后：
```cpp
p -> node -> p 原来的后继
```

关键代码：
```cpp
node->next = p->next;
p->next = node;
```
完整代码：

```c++
void insertAfter(ListNode* p, int x) {
    if (p == nullptr) return;    
    
    ListNode* node = new ListNode(x);    
    node->next = p->next;    
    p->next = node;
}
```
已知插入位置结点 p 时，时间复杂度为 O(1)。
```
重点：
text先让新结点指向 p 原来的后继；再让 p 指向新结点。
```

如果反过来写：
```
p->next = node;
node->next = p->next;
```
会导致原来的后继丢失。
## 3.11 单链表的删除操作
删除单链表中的某个结点时，通常需要知道它的前驱结点。

假设删除 p 后面的结点 q。

原关系：
```
p -> q -> q->next
```

删除后：
```
p -> q->next
```

关键代码：
```cpp
ListNode* q = p->next;
p->next = q->next;
delete q;
```

完整代码：
```cpp
void deleteAfter(ListNode* p) {
    if (p == nullptr || p->next == nullptr) return;    
    
    ListNode* q = p->next;    
    p->next = q->next;    
    delete q;
}
```
已知前驱结点时，删除时间复杂度为 O(1)。

### 按值删除
删除值为 x 的结点时，需要从头开始查找。

推荐使用虚拟头结点 dummy，避免单独处理删除头结点的情况。

时间复杂度：O(n)
空间复杂度：O(1)
## 3.12 顺序表与链表对比

| 对比项      | 顺序表     | 单链表            |
| -------- | ------- | -------------- |
| 存储方式     | 连续存储    | 链式存储           |
| 是否需要连续内存 | 需要      | 不需要            |
| 随机访问     | 支持，O(1) | 不支持，O(n)       |
| 按值查找     | O(n)    | O(n)           |
| 插入操作     | 通常 O(n) | 已知位置时 O(1)     |
| 删除操作     | 通常 O(n) | 已知前驱时 O(1)     |
| 额外空间     | 不需要额外指针 | 每个结点需要 next 指针 |
| 存储密度     | 高       | 较低             |
| 适合场景     | 查询多、修改少 | 插入删除多          |
总结：
```
顺序表：访问快，插入删除慢。
链表：访问慢，插入删除灵活。
```
## 3.13 单链表操作复杂度分析

| 操作 | 时间复杂度 | 原因 |
|---|---:|---|
| 访问第 i 个元素 | O(n) | 需要从头走到第 i 个结点 |
| 按值查找 | O(n) | 需要从头遍历 |
| 遍历 | O(n) | 每个结点访问一次 |
| 已知结点后插入 | O(1) | 只需要修改指针 |
| 已知前驱删除 | O(1) | 只需要修改指针 |
| 头插法单次插入 | O(1) | 直接修改头指针 |
| 尾插法单次插入 | O(1) | 如果维护 tail 指针 |
| 建立长度为 n 的链表 | O(n) | 每个元素建立一个结点 |
注意：
```
链表插入删除 O(1) 的前提是：已经知道插入位置或删除结点的前驱。
如果要先查找位置，整体仍然是 O(n)。
```

# Day 4：链表进阶
## 4.1 双链表
双链表是在单链表基础上增加**前驱指针**的链表。

每个结点包含三个部分：
1. 数据域 val
2. 前驱指针 prev
3. 后继指针 next

双链表既可以向后遍历，也可以向前遍历。

单链表和双链表对比：

| 对比项    | 单链表     | 双链表         |
| ------ | ------- | ----------- |
| 指针数量   | 一个 next | prev 和 next |
| 遍历方向   | 只能向后    | 可向前、向后      |
| 删除当前结点 | 通常需要前驱  | 可直接访问前驱     |
| 空间开销   | 较小      | 较大          |
## 4.2 双链表的插入操作
在双链表中插入结点时，需要同时修改前驱指针和后继指针。

在结点 p 后插入 node：
```cpp
node->next = p->next;
node->prev = p;

if (p->next != nullptr) {
    p->next->prev = node;
}

p->next = node;
```
注意：  
双链表插入时通常要修改 4 条指针。
## 4.3 双链表的删除操作
删除双链表中的某个结点 p 时，需要让 p 的前驱和后继重新连接。

```cpp
if (p->prev != nullptr) {
    p->prev->next = p->next;
}

if (p->next != nullptr) {
    p->next->prev = p->prev;
}

delete p;
```
双链表删除当前结点比单链表更方便，因为可以直接通过 prev 找到前驱。
## 4.4 循环链表
循环链表是一种**首尾相接**的链表。

在循环链表中，最后一个结点的 next 指针不为空，而是指向头结点或第一个数据结点。

循环链表适合需要循环处理数据的场景，例如约瑟夫环问题。
## 4.5 单循环链表
单循环链表是首尾相接的单链表。

特点：
1. 每个结点只有一个 next 指针。
2. 尾结点的 next 指向头结点或第一个数据结点。
3. 遍历时不能用 cur != nullptr 作为结束条件。

注意：
```
循环链表遍历时一定要设置终止条件，否则会死循环。
```
例如：

```cpp
void printCircularList(ListNode* head) {
    if (head == nullptr) return;    
    ListNode* cur = head;    
    do {        
	    cout << cur->val << " ";        
	    cur = cur->next;    
	} while (cur != head);    
	cout << endl;
}
```
## 4.6 双循环链表
双循环链表是在双链表基础上首尾相接。

特点：
1. 每个结点有 prev 和 next 两个指针。
2. 头结点的 prev 指向尾结点。
3. 尾结点的 next 指向头结点。
4. 可以从任意结点向前或向后循环遍历。
## 4.7 链表反转
链表反转的核心是逐个改变结点的 next 指向。

三指针：
- prev：已经反转部分的头结点
- cur：当前正在处理的结点
- nxt：保存 cur 原来的后继

模板：
```cpp
ListNode* reverseList(ListNode* head) {
    ListNode* prev = nullptr;
    ListNode* cur = head;

    while (cur != nullptr) {
        ListNode* nxt = cur->next;
        cur->next = prev;
        prev = cur;
        cur = nxt;
    }

    return prev;
}
```
时间复杂度：O(n)  
空间复杂度：O(1)
## 4.8 合并两个有序链表
合并两个有序链表常用 dummy + tail。

dummy 用于简化头结点处理。
tail 指向结果链表的最后一个结点。

每次比较 list1 和 list2 当前结点，把较小的结点接到 tail 后面。

时间复杂度：O(m + n)
空间复杂度：O(1)
## 4.9 快慢指针
快慢指针是链表中常用的双指针技巧。

通常：
- slow 每次走一步
- fast 每次走两步

常见应用：
1. 找链表中点
2. 判断链表是否有环
3. 找环入口
4. 删除倒数第 k 个结点
## 4.10 判断链表是否有环
使用快慢指针判断链表是否有环。

如果链表无环，fast 会先到达 nullptr。
如果链表有环，fast 会在环中追上 slow。

模板：
```cpp
bool hasCycle(ListNode* head) {
    ListNode* slow = head;
    ListNode* fast = head;

    while (fast != nullptr && fast->next != nullptr) {
        slow = slow->next;
        fast = fast->next->next;

        if (slow == fast) {
            return true;
        }
    }

    return false;
}
```
时间复杂度：O(n)  
空间复杂度：O(1)
## 4.11 找链表中点
使用快慢指针寻找链表中点。

slow 每次走一步，fast 每次走两步。
当 fast 到达链表末尾时，slow 正好位于链表中间。

时间复杂度：O(n)
空间复杂度：O(1)

注意：
如果链表长度为偶数，该模板返回第二个中间结点。
## 4.12 删除倒数第 k 个结点
删除倒数第 k 个结点常用快慢指针。

核心思想：
1. 使用 dummy 结点指向 head。
2. fast 先走 k 步。
3. slow 和 fast 同时向后走（速度均为每次走一步）。
4. 当 fast 到达最后一个结点时，slow 正好在待删除结点的前一个位置。
5. 删除 slow->next。

时间复杂度：O(n)
空间复杂度：O(1)

# Day 5：栈和队列
## 5.1 栈的定义  
栈是一种只允许在一端进行插入和删除操作的线性表。

允许插入和删除的一端称为栈顶，另一端称为栈底。

栈的特点是后进先出，即 LIFO。

最后入栈的元素最先出栈。
## 5.2 栈的基本操作
栈的基本操作包括：
1. push(x)：将元素 x 压入栈顶。
2. pop()：删除栈顶元素。
3. top()：读取栈顶元素。
4. empty()：判断栈是否为空。
5. size()：返回栈中元素个数。

注意：
C++ STL 中 pop() 只负责删除元素，不返回元素。
如果需要获取栈顶元素，应先 top() 再 pop()。
## 5.3 栈的顺序存储

顺序栈使用数组存储元素，并用一个变量表示栈顶位置。

若 topIndex 表示栈顶元素下标：
- 空栈条件：topIndex == -1
- 入栈操作：data[++topIndex] = x
- 出栈操作：topIndex--
- 取栈顶：data[topIndex]

顺序栈的 push、pop、top 操作时间复杂度都是 O(1)。
## 5.4 栈的链式存储
链栈是栈的链式存储实现。

通常使用链表头部作为栈顶，因为头插和头删的时间复杂度都是 O(1)。

链栈特点：
1. 不需要连续存储空间。
2. 栈的大小可以动态变化。
3. 每个结点需要额外的指针空间。
4. push、pop、top 操作时间复杂度都是 O(1)。
## 5.5 栈的典型应用
栈适合处理后进先出的场景。

常见应用包括：
1. 括号匹配
2. 表达式求值
3. 递归调用
4. DFS 非递归实现
5. 单调栈
6. 撤销操作
7. 浏览器历史记录

核心理解：
栈用于处理最近出现、最先解决的问题。
## 5.6 队列的定义
队列是一种只允许在一端插入、另一端删除的线性表。

允许插入的一端称为队尾 rear。
允许删除的一端称为队头 front。

队列的特点是先进先出，即 FIFO。

最先进入队列的元素最先出队。
## 5.7 队列的基本操作
队列的基本操作包括：
1. push(x)：元素 x 入队。
2. pop()：删除队头元素。
3. front()：获取队头元素。
4. back()：获取队尾元素。
5. empty()：判断队列是否为空。
6. size()：返回队列元素个数。

注意：
C++ STL 中 queue 的 pop() 只删除元素，不返回元素。
## 5.8 队列的顺序存储
顺序队列使用数组存储元素，并用 front 和 rear 表示队头和队尾。

通常：
- front 指向队头元素。
- rear 指向队尾元素的**下一个**位置。

入队：
data[rear++] = x

出队：
front++

普通顺序队列的问题是**假溢出**（循环队列解决该问题）：
数组前面有空位，但 rear 已经到达数组末尾，导致无法继续入队。
## 5.9 队列的链式存储
链队列是队列的链式存储实现。

通常维护两个指针：
- front：指向队头结点
- rear：指向队尾结点

入队时在队尾插入。
出队时删除队头结点。

链队列的 push、pop、front 操作时间复杂度都是 O(1)。
## 5.10 循环队列
循环队列将数组首尾相连，把顺序存储空间看作一个环。

当 front 或 rear 到达数组末尾时，可以通过**取模运算**回到数组开头。

核心公式：
rear = (rear + 1) % capacity
front = (front + 1) % capacity

循环队列可以解决普通顺序队列的假溢出问题。
## 5.11 循环队列的队空与队满
循环队列需要区分队空和队满。

常用方法：牺牲一个存储单元。

此时：
- 队空条件：front == rear
- 队满条件：(rear + 1) % capacity == front

如果题目要求队列最多存 k 个元素，数组容量通常开 k + 1。
## 5.12 C++ STL：stack
C++ STL 中可以使用 stack 表示栈。

头文件：

```cpp
#include <stack>
```

常用操作：

|操作|含义|
|---|---|
|push(x)|入栈|
|pop()|出栈|
|top()|获取栈顶|
|empty()|判断是否为空|
|size()|元素个数|

注意：  
stack 不能像数组一样随机访问，只能访问栈顶元素。
## 5.13 C++ STL：queue
C++ STL 中可以使用 queue 表示队列。

头文件：
```cpp
#include <queue>
```

常用操作：

|操作|含义|
|---|---|
|push(x)|入队|
|pop()|出队|
|front()|获取队头|
|back()|获取队尾|
|empty()|判断是否为空|
|size()|元素个数|

queue 只能在队尾插入，在队头删除。

## 5.14 C++ STL：deque
deque 是双端队列，可以在队头和队尾进行插入和删除。

头文件：

```cpp
#include <deque>
```

常用操作：

|操作|含义|
|---|---|
|push_back(x)|尾部插入|
|push_front(x)|头部插入|
|pop_back()|删除尾部|
|pop_front()|删除头部|
|front()|获取头部元素|
|back()|获取尾部元素|

deque 比 queue 更灵活。

## 5.15 栈和队列对比

| 对比项 | 栈 Stack | 队列 Queue |
|---|---|---|
| 操作位置 | 只在栈顶插入和删除 | 队尾插入，队头删除 |
| 访问规则 | 后进先出 LIFO | 先进先出 FIFO |
| 插入操作 | push | push |
| 删除操作 | pop | pop |
| 取元素 | top | front / back |
| 典型应用 | 括号匹配、递归、DFS | BFS、任务调度、缓冲区 |
核心记忆：
```
栈：后进先出，像一摞盘子。队列：先进先出，像排队买饭。
```

# Day 6：栈和队列应用

## 6.1 栈的应用场景总结
栈适合处理后进先出的场景。

常见应用：
1. 括号匹配
2. 表达式求值
3. 中缀表达式转后缀表达式
4. 递归调用
5. DFS 非递归实现
6. 单调栈
7. 撤销操作
8. 浏览器历史记录

你可以这样理解：
```
遇到一个暂时不能立刻处理的问题，就先压入栈；等到后面遇到匹配条件时，再把最近的那个问题弹出来处理。
```
括号匹配就是最典型的例子。
## 6.2 括号匹配问题
括号匹配是栈的经典应用。

算法思路：
1. 遇到左括号，将其压入栈。
2. 遇到右括号，判断栈是否为空。
3. 如果栈为空，说明没有对应的左括号，匹配失败。
4. 如果栈不为空，检查栈顶左括号是否与当前右括号匹配。
5. 如果匹配，则弹出栈顶。
6. 如果不匹配，则匹配失败。
7. 遍历结束后，如果栈为空，说明全部匹配成功；否则失败。

时间复杂度：O(n)
空间复杂度：O(n)

C++ 模板：
```cpp
bool isValid(string s) {
    stack<char> st;

    for (char c : s) {
        if (c == '(' || c == '[' || c == '{') {
            st.push(c);
        } else {
            if (st.empty()) return false;

            char top = st.top();
            st.pop();

            if (c == ')' && top != '(') return false;
            if (c == ']' && top != '[') return false;
            if (c == '}' && top != '{') return false;
        }
    }

    return st.empty();
}
```
## 6.3 表达式的三种形式

表达式主要有三种表示方式：
1. 前缀表达式：运算符在操作数前面。
2. 中缀表达式：运算符在两个操作数中间。
3. 后缀表达式：运算符在操作数后面。
注意：前、中、后是表示操作符的位置。


示例：

| 类型 | 示例 |
|---|---|
| 前缀表达式 | + 1 2 |
| 中缀表达式 | 1 + 2 |
| 后缀表达式 | 1 2 + |
在数据结构中，重点掌握：
```
中缀表达式转后缀表达式

后缀表达式求值
```
## 6.4 中缀表达式

中缀表达式是人类常用的表达式形式。

例如：
1 + 2 * 3

中缀表达式的特点：
1. 运算符位于两个操作数中间。
2. 需要考虑运算符优先级。
3. 需要考虑括号。
4. 计算机直接处理起来不如后缀表达式方便。

## 6.5 后缀表达式 / 逆波兰表达式

后缀表达式又称**逆波兰表达式**。

特点：
1. 运算符位于操作数之后。
2. 不需要括号。
3. 不需要考虑运算符优先级。
4. 适合用栈进行求值。

示例：
中缀表达式：
1 + 2 * 3

后缀表达式：
1 2 3 * +

求值过程：
1. 遇到数字入栈。
2. 遇到运算符，弹出两个操作数。
3. 计算结果后重新入栈。
4. 最后栈中剩下的元素就是表达式结果。

## 6.6 中缀表达式转后缀表达式

中缀表达式转后缀表达式需要使用运算符栈。

规则：
1. 遇到操作数，直接输出。
2. 遇到左括号，压入栈。
3. 遇到右括号，弹出栈顶运算符并输出，直到遇到左括号。
4. 遇到运算符，如果栈顶运算符优先级大于等于当前运算符，则弹出栈顶并输出。
5. 当前运算符入栈。
6. 扫描结束后，将栈中剩余运算符依次弹出并输出。

示例：
中缀表达式：1 + 2 * 3
后缀表达式：1 2 3 * +

简单优先级函数：

```cpp
int priority(char op) {    
	if (op == '+' || op == '-') return 1;    
	if (op == '*' || op == '/') return 2;    
	return 0;
}
```
## 6.7 后缀表达式求值

后缀表达式求值使用栈完成。

算法步骤：
1. 从左到右扫描表达式。
2. 遇到数字，将其压入栈。
3. 遇到运算符，从栈中弹出两个操作数。
4. 先弹出的是右操作数 b，后弹出的是左操作数 a。
5. 计算 a op b。
6. 将结果重新压入栈。
7. 扫描结束后，栈顶元素就是最终结果。

时间复杂度：O(n)
空间复杂度：O(n)

注意：
减法和除法中，操作数顺序不能反。

C++ 模板：

```cpp
int evalRPN(vector<string>& tokens) {    
	stack<int> st;    
	
	for (string token : tokens) {        
		if (token == "+" || token == "-" || token == "*" || token == "/") {        
			int b = st.top();            
			st.pop();            
		
			int a = st.top();            
			st.pop();            
		
			if (token == "+") st.push(a + b);            
			else if (token == "-") st.push(a - b);            
			else if (token == "*") st.push(a * b);            
			else if (token == "/") st.push(a / b);        
		} else {            
			st.push(stoi(token));        
		}    
	}    
	
	return st.top();
}
```
## 6.8 栈与递归调用

递归调用依赖系统调用栈。

每一次函数调用，系统都会保存当前函数的局部变量、返回地址等信息。

递归深入时，相当于不断入栈。
递归返回时，相当于不断出栈。

因此，递归深度过大可能导致栈溢出。

## 6.9 队列的应用场景总结

队列适合先进先出的场景。

常见应用：
1. BFS 广度优先搜索
2. 树的层序遍历
3. 任务调度
4. 消息队列
5. 缓冲区
6. 滑动窗口

最重要的算法应用是：
```
BFS
```

## 6.10 BFS 中的队列
BFS 是广度优先搜索，按照层次逐层访问。

BFS 使用队列的原因：
1. 队列是先进先出。
2. 先发现的结点应该先被扩展。
3. 这样可以保证按层次访问。

BFS 基本步骤：
1. 起点入队。
2. 标记起点已访问。
3. 队列不为空时，取出队头结点。
4. 遍历该结点的所有邻接点。
5. 未访问过的邻接点入队并标记。

时间复杂度：O(V + E)
空间复杂度：O(V)

BFS 常用于：
```
1. 无权图最短路径
2. 层序遍历
3. 连通块搜索
4. 迷宫最短步数
```
## 6.11 DFS 中的栈与递归
DFS 是深度优先搜索。

DFS 的特点：
1. 尽可能沿着一条路径深入。
2. 走不下去时回溯。
3. 递归实现本质上依赖系统调用栈。
4. 非递归实现可以手动使用 stack。

DFS 常用于：
1. 连通性判断
2. 路径搜索
3. 拓扑相关问题
4. 回溯搜索

# Day 7：递归与树的基础
## 7.1 递归的基本思想
递归是指一个函数在定义中直接或间接调用自身。

递归的本质是将一个大问题拆成结构相同的小问题。

例如：
factorial(n) = n * factorial(n - 1)

递归适合处理具有重复子结构的问题，例如树、图搜索、分治、回溯等。
## 7.2 递归三要素
写递归时必须明确三个问题：
1. 函数含义：这个递归函数要解决什么问题。
2. 递归终止条件：递归什么时候停止。
3. 递归转移关系：大问题如何转化为小问题。

如果没有终止条件，递归会无限调用，导致栈溢出。
## 7.3 递归与迭代的区别
递归通过函数调用自身解决问题，迭代通过循环解决问题。

递归代码通常更简洁，适合树形结构、分治和回溯问题。

迭代通常空间开销更小，更适合简单重复操作。

递归的缺点是会产生函数调用栈开销，递归过深可能导致栈溢出。
## 7.4 递归调用栈
递归调用依赖系统调用栈。

每一次函数调用，系统都会保存当前函数的局部变量、参数和返回地址。

递归深入时，相当于不断入栈。
递归返回时，相当于不断出栈。

递归深度过大时，可能导致栈溢出。
## 7.5 树的定义
树是一种非线性数据结构。

树由 n 个结点组成，其中有且只有一个根结点。

除根结点外，其余结点可以分成若干个互不相交的子树。

树体现的是一种一对多的层次关系。
## 7.6 树的基本术语
树的常见术语：
1. 根结点：树中唯一没有前驱的结点。
2. 父结点：某结点的**直接上层**结点。
3. 孩子结点：某结点的**直接下层**结点。
4. 兄弟结点：具有同一个父结点的结点。
5. 祖先结点：从根到该结点路径上的所有上层结点。
6. 子孙结点：某结点下面的所有后代结点。
7. 叶子结点：没有孩子的结点。
8. 分支结点：至少有一个孩子的结点。
9. 子树：某结点及其所有后代组成的树。
10. 路径：从一个结点到另一个结点经过的结点序列。
## 7.7 树的度、结点的度、叶子结点
结点的度：某个结点拥有的**孩子结点个数**。

树的度：树中所有结点的度的最大值。

叶子结点：度为 0 的结点，也就是没有孩子的结点。

分支结点：度不为 0 的结点。
## 7.8 树的深度与高度
结点深度：从根结点到该结点的层数。

结点高度：从该结点到最远叶子结点的最长路径长度。

树的高度通常指根结点的高度，也可以理解为树的最大层数。

常见约定：
- 根结点深度为 1。
- 空树高度为 0。
- 只有一个结点的树高度为 1。

注意：
不同教材对高度和深度的定义可能略有差别，考试时以课件为准。
## 7.9 二叉树的定义
二叉树是每个结点最多有两个孩子的树。

二叉树的两个子树分别称为左子树和右子树。

注意：
二叉树中每个结点最多有两个孩子，不代表每个结点都必须有两个孩子。

二叉树是有序树，左子树和右子树不能随意交换。

重点记：
```
二叉树是有序的。
左子树和右子树的位置有区别。
```
## 7.10 二叉树的五种基本形态
二叉树有五种基本形态：
1. 空二叉树。
2. 只有根结点。
3. 只有左子树。
4. 只有右子树。
5. 左右子树都存在。

二叉树允许某个结点只有左孩子或只有右孩子。
## 7.11 满二叉树
满二叉树是每一层结点数都达到最大值的二叉树。

特点：
1. 除叶子结点外，每个结点都有两个孩子。
2. 所有叶子结点都在同一层。
3. 高度为 h 的满二叉树共有 2^h - 1 个结点。
4. 第 i 层最多有 2^(i-1) 个结点。
## 7.12 完全二叉树
完全二叉树是指：

除最后一层外，其余各层结点数都达到最大；
最后一层的结点从左到右连续排列。

完全二叉树的特点：
1. 适合用数组存储。
2. 堆通常是一棵完全二叉树。
3. 结点编号后，父子关系可以通过下标计算。

完全二叉树数组下标关系，如果从 `1` 开始编号：
```
父结点：i / 2
左孩子：2 * i
右孩子：2 * i + 1
```

如果从 `0` 开始编号：
```
父结点：(i - 1) / 2
左孩子：2 * i + 1
右孩子：2 * i + 2
```
## 7.13 平衡二叉树
平衡二叉树是一类高度尽量保持平衡的二叉树。

在 AVL 树中，对任意结点都有：

| 左子树高度 - 右子树高度 | <= 1

也就是每个结点的左右子树高度差不超过 1。

平衡的目的：
避免二叉搜索树退化成链表，从而保持较高的查找效率。
## 7.14 二叉树的链式存储
二叉树常用链式存储方式。

每个结点包括：
1. 数据域 val
2. 左孩子指针 left
3. 右孩子指针 right

C++ 定义：
```cpp
struct TreeNode {
    int val;
    TreeNode* left;
    TreeNode* right;

    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};
```

# Day 8：二叉树遍历
## 8.1 二叉树遍历的基本概念
二叉树遍历是按照某种顺序访问树中的所有结点。

常见遍历方式：
1. 前序遍历：根、左、右
2. 中序遍历：左、根、右
3. 后序遍历：左、右、根
4. 层序遍历：按层从上到下、从左到右

前三种遍历属于深度优先遍历 DFS。
层序遍历属于广度优先遍历 BFS。
## 8.2 前序遍历
前序遍历顺序：
根 -> 左子树 -> 右子树

口诀：
根左右

递归模板：
```cpp
void preorder(TreeNode* root) {
    if (root == nullptr) {
        return;
    }

    cout << root->val << " ";
    preorder(root->left);
    preorder(root->right);
}
```
前序遍历常用于：
- 复制二叉树
- 输出树的结构
- 前缀表达式
## 8.3 中序遍历
中序遍历顺序：
左子树 -> 根 -> 右子树

口诀：
左根右

递归模板：
```cpp
void inorder(TreeNode* root) {
    if (root == nullptr) {
        return;
    }

    inorder(root->left);
    cout << root->val << " ";
    inorder(root->right);
}
```
中序遍历的重要性质：
对于二叉搜索树 BST，中序遍历结果是有序序列。
## 8.4 后序遍历
后序遍历顺序：
左子树 -> 右子树 -> 根

口诀：
左右根

递归模板：

```cpp
void postorder(TreeNode* root) {
    if (root == nullptr) {
        return;
    }

    postorder(root->left);
    postorder(root->right);
    cout << root->val << " ";
}
```
后序遍历常用于：
- 删除二叉树
- 计算子树信息
- 计算树高
- 目录大小统计
## 8.5 层序遍历
层序遍历按照从上到下、从左到右的顺序访问结点。

层序遍历使用**队列**实现。

步骤：
1. 根结点入队。
2. 当队列不为空时，取出队头结点。
3. 访问该结点。
4. 左孩子不为空则入队。
5. 右孩子不为空则入队。

层序遍历属于 BFS。
## 8.6 递归遍历的统一理解
前序、中序、后序遍历的递归框架相同。

```cpp
void traverse(TreeNode* root) {
    if (root == nullptr) return;

    // 前序位置
    traverse(root->left);

    // 中序位置
    traverse(root->right);

    // 后序位置
}
```
区别在于访问根结点的位置：
- 在递归左子树之前访问根：前序
- 在左右子树之间访问根：中序
- 在递归右子树之后访问根：后序
## 8.7 前序遍历的非递归实现
前序遍历使用栈实现。

因为栈是后进先出，为保证左子树先访问，必须：

先压右孩子，再压左孩子。

时间复杂度：O(n)
空间复杂度：O(h) 到 O(n)
## 8.8 中序遍历的非递归实现
中序遍历非递归实现的核心：
1. 当前结点不为空时，不断向左走并入栈。
2. 走到空结点后，弹出栈顶并访问。
3. 转向该结点的右子树。
4. 重复以上过程。

模板：
```cpp
while (cur != nullptr || !st.empty()) {
    while (cur != nullptr) {
        st.push(cur);
        cur = cur->left;
    }

    cur = st.top();
    st.pop();

    visit(cur);

    cur = cur->right;
}
```
## 8.9 后序遍历的非递归实现
后序遍历可以先得到“根、右、左”，再整体反转。

后序：
左、右、根

反转后：
根、右、左

实现步骤：
1. 根结点入栈。
2. 弹出结点并记录。
3. 先压左孩子，再压右孩子。
4. 最后反转结果数组。
## 8.10 层序遍历的队列实现

如果需要区分每一层，应在处理当前层之前记录：

```cpp
int levelSize = q.size();
```
这表示当前层一共有多少个结点。

处理这 levelSize 个结点时，它们的孩子会进入队列，构成下一层。

因此不能直接把变化中的 q.size() 作为循环上限。
## 8.11 根据遍历序列还原二叉树
可以唯一还原二叉树的常见组合：
- 前序遍历 + 中序遍历
- 后序遍历 + 中序遍历

原因：
- 前序第一个元素是根
- 后序最后一个元素是根
- 中序可以区分左子树和右子树

仅有前序和后序，一般不能唯一确定二叉树。
## 8.12 四种遍历方式对比

| 遍历方式 | 顺序   | 主要结构 | 常见应用          |
| ---- | ---- | ---- | ------------- |
| 前序遍历 | 根左右  | 递归或栈 | 复制树、输出结构      |
| 中序遍历 | 左根右  | 递归或栈 | BST 有序输出      |
| 后序遍历 | 左右根  | 递归或栈 | 删除树、统计子树信息    |
| 层序遍历 | 按层访问 | 队列   | BFS、最短层数、层级输出 |
口诀必须熟记：
```
前序：根左右中序：左根右后序：左右根层序：从上到下、从左到右
```
## 8.13 遍历复杂度分析
前序、中序、后序、层序遍历都会访问每个结点一次。

时间复杂度均为：
O(n)

递归遍历的空间复杂度取决于递归深度：
O(h)

其中 h 是树高。

层序遍历的空间复杂度取决于队列中最多保存的结点数，最坏为 O(n)。

# Day 9：二叉搜索树 BST
## 9.1 二叉搜索树的定义
二叉搜索树是一种具有有序性质的二叉树。

对于任意结点 root：
- 左子树中的所有结点值都小于 root->val。
- 右子树中的所有结点值都大于 root->val。
- 左右子树本身也都是二叉搜索树。
## 9.2 BST 的核心性质
BST 的核心性质：
1. 左子树所有结点值小于根。
2. 右子树所有结点值大于根。
3. 左右子树也满足 BST 性质。
4. BST 的中序遍历结果是递增序列。
5. 查找时可以根据大小关系只进入一侧子树。
## 9.3 BST 与普通二叉树的区别
普通二叉树只限制每个结点最多有两个孩子。

BST 在此基础上还要求左子树小于根，右子树大于根。

因此 BST 可以利用大小关系缩小查找范围。
## 9.4 BST 的查找
BST 查找时，根据目标值与当前结点值的关系决定搜索方向：
- 相等：查找成功。
- 目标值较小：进入左子树。
- 目标值较大：进入右子树。
- 到达 nullptr：查找失败。

平均时间复杂度：O(log n)
最坏时间复杂度：O(n)

注意：
```
BST 查找不需要同时搜索左右子树
```

因为大小关系已经告诉我们目标只可能在哪一边。
## 9.5 BST 的最小值与最大值
在 BST 中：
- 最左侧结点是最小值。
- 最右侧结点是最大值。

寻找最小值：不断访问 left。
寻找最大值：不断访问 right。
## 9.6 BST 的插入
BST 插入时，从根结点开始比较：
- 插入值小于当前结点，进入左子树。
- 插入值大于当前结点，进入右子树。
- 遇到空位置时创建新结点。
- 插入后仍需满足 BST 性质。

新结点总是插入到叶子位置。
## 9.7 BST 的删除
BST 删除结点分为三种情况：
1. 删除叶子结点：直接删除。
2. 删除只有一个孩子的结点：让其父结点直接连接它的孩子。
3. 删除有两个孩子的结点：
   - 找右子树中的最小结点，或
   - 找左子树中的最大结点，
   用其值替换当前结点，再删除替代结点。
### A. 删除叶子结点
例如删除 `2`：
```
删除前：
        8
       /      
      4     
     /    
    2
```

`2` 没有孩子，所以可以直接删除：

```
删除后：
        8
       /
      4
```

代码逻辑：

```c++
if (root->left == nullptr && root->right == nullptr) {
    delete root;
    return nullptr;
}
```

实际代码中，叶子结点通常会被“只有零个或一个孩子”的统一逻辑处理。
### B. 删除只有一个孩子的结点
例如删除 `4`：
```
删除前：
        8
       /
      4
       \
        6
```
`4` 只有右孩子 `6`。

```
删除后：
        8
       /
      6
```
也就是让 `4` 的父结点直接连接 `6`。

代码：
```c++
if (root->left == nullptr) {
    TreeNode* rightChild = root->right;
    delete root;
    return rightChild;
}

if (root->right == nullptr) {
    TreeNode* leftChild = root->left;
    delete root;
    return leftChild;
}
```

Q：为什么要返回孩子？

A：因为递归调用处需要重新连接父结点：
```cpp
root->left = deleteNode(root->left, key);
```
返回孩子后，相当于让父结点绕过被删除结点，直接连接它的孩子。
### C.  删除有两个孩子的结点
这是**最关键**的情况。

例如删除根结点 `8`：
```
        8      
      /   \
     4     12
          /  \
         10  14
```
不能直接把 `8` 删除，因为左右两棵子树都需要保留。

常用方法是找到：
```
右子树中的最小结点
```
右子树中最小的是 `10`。

用 `10` 替换 `8`：
```
        10
      /    \ 
     4      12
           /  \
          10  14
```

此时有两个 `10`，所以还要继续删除右子树中原来的 `10`：
```
        10
      /    \
     4      12
              \
               14
```

Q：为什么可以用右子树最小值替换？
A：因为右子树最小值满足：
```
它大于左子树中的所有值它不大于右子树中其他值
```

所以替换后仍满足 BST 性质。

代码：
```cpp
TreeNode* successor = findMin(root->right);
root->val = successor->val;
root->right = deleteNode(root->right, successor->val);
```

也可以使用：
```
左子树中的最大值
```
原理相同。
## 9.8 BST 的中序遍历
BST 中序遍历结果是**递增序列**。

因此，很多 BST 问题都可以转化为对有序序列的处理。
## 9.9 BST 的前驱与后继
对于某个结点：
```
前驱：中序遍历中位于它前面的结点
后继：中序遍历中位于它后面的结点
```

例如 BST 的中序序列：
```
2 4 6 8 10 12 14
```

对于 `8`：
```
前驱是 6后继是 10
```

在 BST 中：
```
如果结点有左子树：前驱是左子树中的最大值
如果结点有右子树：后继是右子树中的最小值
```
这也是删除有两个孩子的结点时使用前驱或后继替代的原因。
## 9.10 BST 的复杂度分析
BST 查找、插入、删除的复杂度都与树高 h 有关：
O(h)

平衡情况下：
h ≈ log n
因此平均复杂度为 O(log n)。

最坏情况下树退化为链表：
h = n
因此最坏复杂度为 O(n)。
## 9.11 BST 退化问题
普通 BST **不保证平衡**。

如果插入序列本身有序，BST 可能退化为链表。

退化后：
- 树高从 O(log n) 变为 O(n)
- 查找、插入、删除也退化为 O(n)

因此需要 AVL 树、红黑树等平衡搜索树。

# Day 10：AVL 树 / 平衡树基础
## 10.1 为什么需要平衡树  
普通 BST 的查找效率取决于树的高度。  
  
如果 BST 比较平衡，树高约为 log n，查找效率较高。  
  
如果 BST 退化成链表，树高变为 n，查找效率退化为 O(n)。  
  
因此需要平衡树来控制树的高度，使查找、插入、删除保持较高效率。
## 10.2 普通 BST 的退化问题
普通 BST 不会自动保持平衡。

当插入序列接近有序时，BST 可能退化成链表。

退化后的影响：
1. 树高从 O(log n) 变为 O(n)。
2. 查找复杂度从 O(log n) 退化为 O(n)。
3. 插入和删除也会退化为 O(n)。
## 10.3 平衡二叉树的定义
平衡二叉树是一类尽量保持左右子树高度接近的二叉搜索树。

它的目标是避免 BST 退化成链表，从而保证较高的查找效率。

常见平衡树：
- AVL 树
- 红黑树
- B 树
- B+ 树
## 10.4 AVL 树的定义
AVL 树是一种自平衡二叉搜索树。

AVL 树必须满足：
1. 它首先是一棵 BST。
2. 对任意结点，其左子树和右子树高度差的绝对值不超过 1。

即：
|height(left) - height(right)| <= 1

AVL 树通过旋转操作在插入或删除后恢复平衡。
## 10.5 平衡因子 BF
平衡因子 BF 表示一个结点左右子树高度的差值。

BF = 左子树高度 - 右子树高度

AVL 树要求每个结点的 BF 只能是 -1、0、1。

如果 BF = 2，说明左子树过高。
如果 BF = -2，说明右子树过高。

当 BF 超出范围时，需要通过旋转恢复平衡。
## 10.6 AVL 树的高度与复杂度
AVL 树通过保持左右子树高度平衡，使树高维持在 O(log n)。

因此 AVL 树的查找、插入、删除操作都能保持 O(log n)。

相比普通 BST，AVL 树的优势是最坏情况下也能保持较高效率。
## 10.7 AVL 插入后的失衡情况
AVL 插入后可能出现四种失衡类型：
1. LL 型：插入到左子树的左侧。
2. RR 型：插入到右子树的右侧。
3. LR 型：插入到左子树的右侧。
4. RL 型：插入到右子树的左侧。

LL 和 RR 只需要一次旋转。
LR 和 RL 需要两次旋转。
## 10.8 LL 型失衡
LL 型失衡是指新结点插入到失衡结点左孩子的左子树。

形态：
```
	  z
	 /
	y
   /
  x
```

解决方法：
对 z 进行右旋。

旋转后：
```
    y
   / \
  x   z
```
## 10.9 RR 型失衡
RR 型失衡是指新结点插入到失衡结点右孩子的右子树。

形态：
```
z
 \
  y
   \
    x
```

解决方法：
对 z 进行左旋。

旋转后：
```
    y
   / \
  z   x
```
## 10.10 LR 型失衡

LR 型失衡是指新结点插入到失衡结点左孩子的右子树。

形态：
```
    z
   /
  y
   \
    x

```

解决方法：
1. 先对 y 左旋。
2. 再对 z 右旋。

口诀：
LR 先左旋，再右旋。
## 10.11 RL 型失衡
RL 型失衡是指新结点插入到失衡结点右孩子的左子树。

形态：
```
z
 \
  y
 /
x
```

解决方法：
1. 先对 y 右旋。
2. 再对 z 左旋。

口诀：
RL 先右旋，再左旋。
## 10.12 AVL 树与 BST 的关系
AVL 树是一种自平衡 BST。

AVL 树一定满足 BST 性质，即左小右大。

但普通 BST 不一定满足 AVL 的平衡条件。

关系：
AVL 树 ⊂ BST

也就是说，AVL 树一定是 BST，但 BST 不一定是 AVL 树。
