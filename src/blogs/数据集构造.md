# 一、一些数据集介绍
## 1、Easy Turn [Github](https://github.com/ASLP-lab/Easy-Turn)
### Easy Turn Trainset
Easy Turn Trainset 是一个用于检测对话中轮流发言情况的大规模音频数据集，其中包含了真实对话和合成数据。该数据集包含四个子集，分别对应不同的对话状态：580 小时的完整对话数据、532 小时的不完整对话数据、10 小时的背景音数据，以及 23 小时的等待状态数据。总而言之，该数据集的总时长约为 1,100 小时。每段录音都配有文字记录，并被标记为上述四种对话状态中的一种。

### Data Types
1. raw
```
{
"task": "<TRANSCRIBE> <BACKCHANNEL> <COMPLETE>",  #固定或自行参考conf/prompt.yaml
"key": "complete_0001",  #必填
"wav": "./complete_0001.wav",  #必填
"txt": "你有没有发生过一些童年趣事呀？<COMPLETE>", #必填，抄本结尾带四种标签之一（<COMPLETE>，<INCOMPLETE>，<BACKCHANNEL>，<WAIT>）
"lang": "<CN>", 
"speaker": "G00000007", #非必需，可填<NONE>
"emotion": "<NONE>", #非必需，可填<NONE>
"gender": "female", #非必需，可填<NONE>
"duration": 3.256, #非必需，可填0
"state": "0", #非必需，可填0
"extra": {"dataset": "magicdata_ramc"} #非必需，可为空
}
```
2. shard（分片数据）：数据被打包到 tar 文件中，将多个条目存储在一起，从而实现高效的数据批量加载。



  ## 第一步：实现门禁人工抽检工具

  需要先实现一个工具，同时从以下两类样本中抽样：

  - accepted：检查是否存在错误放行。
  - review/rejected：检查是否存在错误拦截，以及哪些样本可以修复。

  工具需要自动：

  1. 按backchannel/complete/incomplete/wait分层抽样。
  2. 从训练shard和隔离shard导出普通WAV。
  3. 生成统一的人工检查JSONL。
  4. 记录官方文本、Paraformer文本、CER和边界差。
  5. 接收人工判断并统计误放行率、误拦截率。
  6. 根据检查结果生成门禁抽检报告。

  这一步由我继续实现，你暂时不需要执行命令。

  ## 第二步：生成Easy-Turn calibration数据

  第一步工具完成后，分别处理：

  backchannel_real：100条
  complete_real：100条
  incomplete_real：100条
  wait：100条

  共400条。处理时同时运行：

  fa-zh强制对齐
  → Paraformer独立识别
  → 当前候选门禁
  → accepted/隔离分流

  这一步使用--max-samples 100，属于校准，不是正式训练数据。

  ## 第三步：执行人工抽检

  运行第一步实现的工具，从400条中导出：

  - accepted样本
  - review样本
  - rejected样本
  - 对应WAV
  - 人工检查表

  然后你需要试听并填写：

  官方文本是否正确
  fa-zh时间是否可用
  当前门禁是否判断正确
  最终应接受、修正、隔离还是淘汰

  只检查隔离样本不够，必须同时检查accepted样本。

• 这里的“第三步人工抽验”主要是在验证ASR一致性门禁是否判断正确，不是重新标注Easy-Turn官方的complete/incomplete/backchannel标签。

  你需要人工判断两件事：

  1. 官方文字是否符合实际语音。
  2. fa-zh生成的token时间是否能用于160ms流式训练。

  ## 二、推荐使用Audacity检查

  服务器通常没有图形界面，建议把整个抽验目录下载到本地电脑，约53MiB，然后使用Audacity。

  对于每个样本：

  1. 在Audacity中打开WAV。
  2. 选择“文件 → 导入 → 标签”。
  3. 导入同名的*.fa.labels.txt。
  4. 再导入*.paraformer.labels.txt。
  5. 给两个标签轨道分别命名为fa-zh和Paraformer。
  6. 放大波形，边听边查看token起止位置。

  标签文件格式为：

  起始秒    结束秒    token

  例如：

  0.110    0.350    哦
  0.370    0.510    对
  0.510    0.650    对
  0.650    0.805    对

  ## 三、第一遍：只判断官方文本

  先不要看Paraformer文本和当前门禁结果，避免先入为主。

  试听WAV，并将实际听到的内容与official_text比较。

  ### 可以判定文本正确

  以下差异通常不算错误：

  - 逗号、句号、问号差异；
  - 空格差异；
  - 不影响实际发音的书写格式差异。

  以下情况通常算文本错误：

  - “嗯”实际说成“哦”；
  - 漏掉开头或结尾语气词；
  - 多写或少写词；
  - 录音与文本完全不对应；
  - 数字、姓名或关键词明显错误；
  - 音频已经截断，但文本仍包含未说出的后半句。

  填写：

  "transcript_correct": true

  或者：

  "transcript_correct": false

  听不清时填写：

  "transcript_correct": null

  ## 四、第二遍：判断fa-zh时间是否可用

  重点查看fa-zh标签轨道，而不是要求毫秒级绝对准确。

  Stage 3把token结束时间映射到160ms chunk：

  token结束时间
      ↓
  对应的160ms chunk
      ↓
  在该chunk中产生ASR target

  因此，最重要的是token结束时间不能明显过早或过晚。

  ### 可以认为fa-zh可用

  满足以下大部分条件：

  - 每个token标签覆盖对应文字的实际发音；
  - token顺序正确且时间单调；
  - token没有整体提前或延后很多；
  - token结束时间基本位于该字发音结束附近；
  - 最后一个token没有在实际语音结束前就结束；
  - 一般内部token相差不到约一个160ms chunk；
  - 少量相邻字共用相近边界可以接受。

  填写：

  "fa_alignment_usable": true

  ### 应认为fa-zh不可用

  出现以下情况之一：

  - token标签落在静音区域；
  - 某个token标签对应了另一个字；
  - 多个token整体偏移超过约一个160ms chunk；
  - 最后一个token明显提前结束；
  - 最后一个token落在很长的尾部静音后；
  - 某些字时间顺序混乱；
  - 文本正确，但fa-zh强行对到了错误声学位置；
  - 边界错误足以改变流式训练中token出现的chunk。

  填写：

  "fa_alignment_usable": false

  ### 边界判断建议

  - 偏差在160ms以内：通常可以接受。
  - 偏差约160～320ms：结合发音、语速和终止token判断；无法确定可标记uncertain。
  - 明显超过320ms：通常不能直接接受。
  - incomplete样本尤其关注最后一个token，因为它直接影响“用户尚未说完”的状态训练。
  - backchannel很短，一个字偏移一个chunk就可能影响很大。

  这里是人工工程标准，不要求找到语言学意义上的绝对音素边界。

  ## 五、第三遍：查看Paraformer和当前门禁

  完成前两项独立判断后，再查看：

  "paraformer_text"
  "current_disposition"
  "quality_reasons"
  "character_error_rate"
  "chunk_boundary_agreement"
  "p95_boundary_delta_ms"
  "terminal_boundary_delta_ms"

  典型判断：

  ### 情况A：官方文本正确，fa-zh也正确

  即使Paraformer识别错，也应该：

  "human_action": "accept_as_is",
  "transcript_correct": true,
  "fa_alignment_usable": true

  如果当前是review/rejected，这就是门禁“错误拦截”。

  ### 情况B：官方文本错误

  填写：

  "human_action": "correct_transcript",
  "transcript_correct": false,
  "fa_alignment_usable": false,
  "corrected_text": "实际听到的正确文本"

  后续会用修正文本重新运行fa-zh和Paraformer。

  ### 情况C：官方文本正确，但fa-zh边界错误

  填写：

  "human_action": "realign",
  "transcript_correct": true,
  "fa_alignment_usable": false

  它表示需要换模型、换参数或人工修正对齐。使用同一个模型和相同参数简单重跑通常没有意义。

  ### 情况D：音频或样本无法修复

  例如音频损坏、多人严重重叠、文本完全错配：

  "human_action": "reject_permanent",
  "transcript_correct": null,
  "fa_alignment_usable": null

  ### 情况E：无法确定

  "human_action": "uncertain",
  "transcript_correct": null,
  "fa_alignment_usable": null

  所有已填写human_action的行，包括uncertain，都必须填写reviewer和reason。

  ### 修正文本

  "fa_alignment_usable": false,
  "corrected_text": null,

  "reason": "文本正确，但最后一个token提前约400ms结束",
  "reviewed_at": "2026-07-14"

  ## 七、建议的人工工作方式

  不要一次连续听486条。建议：

  每批20～30条
  → 保存JSONL
  → 生成中期报告
  → 休息
  → 继续下一批

  优先顺序：

  1. accepted中的complete/incomplete：检查错误放行。
  2. review/rejected中的complete/incomplete：检查错误拦截。
  3. backchannel：重点检查嗯/哦/啊等短语气词。
  4. wait。
  5. synthetic。
  6. 所有uncertain交给第二个人复核。

  如果条件允许，随机抽取约10%让第二个人重复标注，用于检查人工一致性。

  ## 八、生成中期报告

  完成部分样本后运行：

  cd /root/soulx-duplug-stage3-cn-replacement

  bash scripts/audit_alignment_gate.sh \
    --audit-dir calibration/easyturn_alignment_gate_candidate_v1 \
    --decisions calibration/easyturn_alignment_gate_candidate_v1/audit_decisions.jsonl \
    --report-md calibration/easyturn_alignment_gate_candidate_v1/audit_report.interim.md \
    --report-json calibration/easyturn_alignment_gate_candidate_v1/audit_report.interim.json \
    --allow-incomplete

  工具会自动检查：

  - 是否修改了不可变字段；
  - 决策值是否合法；
  - accept_as_is是否同时满足两个true；
  - correct_transcript是否填写正确文本；
  - realign字段是否一致；
  - reviewer和reason是否填写。

  486条全部完成后，去掉--allow-incomplete生成正式报告。之后才能进入第四步：根据错误放行率和错误拦截率调整并冻结门禁阈值。






  ## 第四步：确定并冻结门禁阈值

  根据人工抽检结果决定是否修改：

  accept CER
  review CER
  字符覆盖率
  160ms chunk一致率
  P95边界差
  终止边界差

  然后生成正式配置：

  configs/alignment_quality/easyturn-stage3-gate-v1.env
  configs/alignment_quality/easyturn-stage3-gate-v1.env.sha256

  从这一步开始，v1不能再修改。要改只能建立v2。

  ## 第五步：删除calibration临时产物

  保存：

  - 人工抽检报告
  - 人工决策表
  - 冻结配置
  - 汇总统计

  然后删除400条calibration生成的WAV和processed shard，释放空间。

  ## 第六步：逐subset正式处理Easy-Turn

  建议顺序：

  1. backchannel_real
  2. backchannel_syn
  3. wait
  4. incomplete_real
  5. complete_real
  6. incomplete_syn
  7. complete_syn

  每次只处理一个subset，并显式加载冻结配置：

  --quality-threshold-config \
  configs/alignment_quality/easyturn-stage3-gate-v1.env

  ## 第七步：处理隔离样本

  每个subset处理完成后：

  8. accepted样本直接保留。
  9. 隔离样本导出WAV。
  10. 人工判断。
  11. 可用样本通过提升工具生成promoted shard。
  12. 无法修复的样本永久淘汰。

  ## 第八步：上传并释放空间

  每个subset完成后：

  校验本地checksum
  → 上传原accepted shard
  → 上传promoted shard
  → 上传manifest、stats和审计文件
  → 校验百度网盘文件
  → 删除本地该subset的processed数据
  → 开始下一个subset
